# Update a scaffolded project

1. **Inspect.** Call `scaffold_inspect_project` with the absolute project path. Confirm it has Copier answers, then note the language, profile and current `templateCommit`.
2. **Clean tree.** `git.clean` must be true. If it isn't, show the user the changes and ask them to commit or stash. Never stash or discard work on your own.
3. **Update.** Call `scaffold_update` (write tier, needs approval). Use `conflict: "inline"` by default; use `"rej"` if the user prefers separate reject files. Pass `ref` only when the user wants a specific template version.
4. **Resolve.**
   - For each entry in `conflicts`, and any file with `<<<<<<<` markers, merge so the project's own changes are kept and the template's intent is adopted.
   - Delete `.rej` files once they're resolved.
   - Never edit `.copier-answers.yml` by hand.
5. **Re-lock and verify.** If dependency manifests changed, reinstall (`uv sync`, `pnpm install`, or `./gradlew build --refresh-dependencies`). Then run the project's `verify` skill or the verification sequence in its `AGENTS.md`.
6. **Report.** Summarize the template changes adopted, the conflicts resolved and the verification results, and suggest a commit message such as `chore: update from project template`. Don't commit unless the user asks.
